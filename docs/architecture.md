# Lume architecture

This document describes Lume across `crates/lume-core/`, `crates/lume-syntax/`, and `crates/lume-tui/` at commit `a8df968`. Each subsystem separates headless editor state from terminal I/O and background parsing while keeping known implementation limits visible beside verified guarantees.

## Crate boundaries and unsafe isolation

The workspace isolates platform-dependent terminal control inside `lume-tui`, leaving `lume-core` and `lume-syntax` in pure safe Rust with zero `unsafe` blocks. Cross-crate boundaries exchange value snapshots, `ropey::Rope` handles (`Arc`-backed copy-on-write trees), and `crossbeam-channel` messages rather than shared mutable references.

Because `lume-core` has no dependency on `crossterm`, `tree-sitter`, or `libc`, unit and property tests verify buffer invariants, undo symmetry, atomic saves, and journal recovery without a terminal. `lume-syntax` sits beside `lume-core` with no direct dependency between them; `lume-tui` bridges both crates by converting `Editor` edits into `ByteDelta` shifts and `SyntaxRequest` payloads.

Only `crates/lume-tui/src/terminal.rs` contains `unsafe` blocks (`crates/lume-tui/src/terminal.rs:44`, `crates/lume-tui/src/terminal.rs:61`). Those blocks capture the initial POSIX `termios` struct and register `SIGINT`, `SIGTERM`, and `SIGHUP` handlers that write raw cleanup sequences and restore terminal attributes before re-raising the signal.

## Text engine and editing invariants

`RopeBuffer` wraps `ropey::Rope` behind the `TextBuffer` trait (`crates/lume-core/src/buffer/mod.rs:43-54`) and checks UTF-8 character boundaries on every write. Calling `insert` or `delete` validates offsets against `len_bytes()` and verifies `char_to_byte(byte_to_char(idx)) == idx`, returning `BufferError` instead of splitting code points (`crates/lume-core/src/buffer/mod.rs:198-239`). Read helpers such as `byte_to_line`, `line_to_byte`, `byte_to_char`, and `char_to_byte` clamp out-of-bounds offsets, while `try_byte_to_char` and `try_char_to_byte` return errors (`crates/lume-core/src/buffer/mod.rs:113-133`).

`CursorSet` stores each cursor as `(anchor, head, affinity)` (`crates/lume-core/src/cursor/mod.rs:8-12`) and normalizes sets via `CursorSet::normalize` (`crates/lume-core/src/cursor/mod.rs:134-190`). Normalization tags `primary_idx` before sorting by `(min, max, orig_idx)`, merges overlapping selections and boundary-touching carets, keeps adjacent non-empty selections such as `[0, 3)` and `[3, 6)` separate, and updates `primary_idx`.

Multi-cursor edits in `Editor` (`crates/lume-core/src/editor/indent.rs` and `crates/lume-core/src/editor/clipboard.rs`) validate cursor char boundaries before mutating the buffer and track cumulative byte offsets across sorted cursors. When an intermediate edit fails, `rollback_deltas` replays earlier deltas in reverse (`crates/lume-core/src/editor/indent.rs:382-391`) so neither the buffer nor `History` retains partial changes.

`History` keeps undo entries in a `VecDeque<HistoryEntry>` capped at `DEFAULT_MAX_UNDO_ENTRIES = 5_000` and `DEFAULT_MAX_HISTORY_BYTES = 50 * 1024 * 1024` bytes (`crates/lume-core/src/history/mod.rs:5-6`). Single-cursor non-whitespace inserts coalesce into the latest undo entry only while `undo_group_open` is true, `redo_stack` is empty, the cursor is away from `saved_depth`, and bytes fit within budget (`crates/lume-core/src/history/mod.rs:121-153`). Calling `undo_with_primary` or `redo_with_primary` rolls back partial sequences via `rollback_buffer_ops` and restores the entry on failure (`crates/lume-core/src/history/mod.rs:187-237`), while `saved_depth` shifts across evictions and resets to `None` when branching edits invalidate a saved future state.

## Persistence, async saves, and crash journal

`Editor::open_in_current_tab` (`crates/lume-core/src/editor/mod.rs:76-144`) validates the target file before mutating tab state. It probes the first `8,192` bytes for NUL (`0x00`), rewinds to load and validate UTF-8 via `RopeBuffer::from_reader`, checks `Journal::is_fresh_for`, stages differing recovery text in `tab.pending_recovery` without marking `is_dirty`, and finally updates tab fields and `git_baseline`.

Saving runs through `Editor::write_buffer_atomically` (`crates/lume-core/src/editor/save.rs:90-162`). `resolve_write_target` follows up to 32 symlink hops (`crates/lume-core/src/editor/save.rs:41-88`); on a dangling symlink with an existing parent directory, it resolves the parent canonically so writes create the target instead of replacing the symlink. Data writes to `.{file_name}.{pid}.{counter}.lume_tmp` with `create_new(true)` (`0o600` on Unix before applying any existing permissions), runs `file.sync_all()`, renames over the target, and runs `dir.sync_all()` on Unix.

Manual `Ctrl+S` (`"file.save"` in `crates/lume-tui/src/commands.rs:230-238`) executes synchronous `Editor::save()` on the UI thread, blocking while `sync_all()` finishes. Non-blocking `Editor::save_async()` (`crates/lume-core/src/editor/save.rs:200-270`) clones the `Rope` in $O(1)$ and spawns a worker thread guarded by `TabSyncState::{save_lock, journal_lock}` and atomic revision flags (`crates/lume-core/src/editor/tab.rs:11-16`). Only `AutoSaveController` (`enabled: false` by default, `debounce: 1000 ms`, `crates/lume-core/src/autosave.rs:9-16`) and `AppEvent::FocusLost` when autosave is enabled (`crates/lume-tui/src/input/mod.rs:42-53`) trigger `save_async()`. Three race boundaries exist in this async path: `save_async()` calls `self.autosave.mark_saved()` before disk I/O finishes (`crates/lume-core/src/editor/save.rs:236`), `open_in_current_tab` neither increments `tab.revision` nor resets `tab.sync_state` (`crates/lume-core/src/editor/mod.rs:125-141`), and `poll_async_saves` matches events by `(tab_id, save_revision)` without checking `ev.path` (`crates/lume-core/src/editor/save.rs:280-311`).

`Journal` (`crates/lume-core/src/journal.rs`) stores per-file recovery logs under `$LUME_JOURNAL_DIR`, `$XDG_CACHE_HOME/lume/journal`, `$HOME/.cache/lume/journal`, or `$TMPDIR/lume_journal_<pid>` (mode `0o700` on Unix) using `{fnv1a_64(resolved_path):016x}_{filename}.journal`. `JournalWorker` processes an unbounded `crossbeam_channel` off the UI thread, collapses consecutive `Snapshot` operations for the same journal path between `AppendDeltas`, `Remove`, and `Flush` barriers (`crates/lume-core/src/journal.rs:55-96`), and flushes via `file.sync_data()`. Journals use `MAGIC` (`LUMJ\x01`, deltas over the disk file) or `MAGIC_V2` (`LUMJ\x02`, `u64` base length + inline UTF-8 base + binary `[start_byte, old_len, old_bytes, new_len, new_bytes, timestamp]` deltas). Three durability limits apply at commit `a8df968`:

- `record_deltas_internal` (during non-V2 upgrades) and `record_snapshot_internal` open the live journal path with `.truncate(true)` instead of writing a temporary file and renaming (`crates/lume-core/src/journal.rs:362`, `crates/lume-core/src/journal.rs:398`).
- Journal records store no CRC or hash checksum to catch torn writes or corrupted lengths.
- Files lacking `LUMJ\x01` or `LUMJ\x02` headers fall back to `String::from_utf8_lossy` (`crates/lume-core/src/journal.rs:476-479`), surfacing corrupt binary content as recovery text.

## Search, fuzzy matching, and Git line diffs

Buffer search (`crates/lume-core/src/search.rs`) uses three matching paths. Case-sensitive searches call `str::match_indices`, single-line ASCII case-insensitive searches scan 8-byte words via SWAR bit masking (`find_ascii_first_byte`, `crates/lume-core/src/search.rs:4-27`) plus `eq_ignore_ascii_case`, and non-ASCII case-insensitive searches stream `char::to_lowercase()` folds (`match_unicode_at`, `crates/lume-core/src/search.rs:29-54`) to handle multi-character expansions like `'İ'` (`"i\u{0307}"`). Multiline queries (`needle.contains('\n')`) copy the entire buffer into a `Cow<str>` via `slice_to_cow(0, len)` (`crates/lume-core/src/search.rs:244-246`).

Quick Open path ranking (`crates/lume-core/src/fuzzy.rs`) splits queries on whitespace and requires every token to appear as a subsequence. ASCII candidates first pass a zero-allocation subsequence scan (`is_subsequence_ascii`, `crates/lume-core/src/fuzzy.rs:25-41`) before calling `match_single_token` (`crates/lume-core/src/fuzzy.rs:131-292`), a recursive memoized dynamic program backed by thread-local `DP_SCRATCHPAD`. Because `solve(p, prev)` loops over `curr in min_c..max_c` at every state, worst-case per-token time is $O(m \cdot n^2)$ in token length $m$ and candidate length $n$. Thread-local `DP_SCRATCHPAD` retains its peak buffer capacity for the thread's lifetime.

Gutter diff markers (`crates/lume-core/src/diff.rs` and `crates/lume-core/src/git.rs`) compare the current `Rope` against `git_baseline` (`git cat-file blob HEAD:<rel_posix>`, capped at `MAX_GIT_HEAD_BLOB_BYTES = 16 MiB` in `crates/lume-core/src/git.rs:177`) or against `clean_snapshot` when dirty outside a Git repository. `compute_rope_diffs` trims common prefix and suffix lines directly on `RopeSlice` values without string allocation, retaining one suffix line so deletions immediately before the suffix mark `LineDiffStatus::DeletedAbove`. The unmatched middle slice runs a flattened 1D LCS table (`u32` cells) and switches to linear `Modified`/`Added` marking whenever `m * n > 250_000` (`crates/lume-core/src/diff.rs:82-98`).

## Background syntax highlighting

`lume-syntax` covers 16 `Language` variants (`crates/lume-syntax/src/language.rs:4-21`). Six languages use compiled Tree-sitter parsers (`C`, `Cpp`, `Rust`, `Python`, `Java`, `JavaScript`), `TypeScript` maps to `tree_sitter_javascript::LANGUAGE` (`crates/lume-syntax/src/language.rs:132`), and eight formats use custom lexers (`Assembly`, `Go`, `Json`, `Toml`, `Yaml`, `Markdown`, `Shell`, `Html`/`Css` in `crates/lume-syntax/src/lexer.rs`). Mapping TypeScript to the JS grammar causes JS parse errors on TS syntax such as `interface` declarations, and `lex_html_css` (`crates/lume-syntax/src/lexer.rs:534-564`) only emits tokens for `<...>` tags in both HTML and CSS buffers.

Parsing runs off the UI thread inside `SyntaxWorker` (`crates/lume-syntax/src/worker.rs:64-162`). The worker drains pending requests, keeps only the latest `SyntaxRequest<Rope>` per `buffer_id` in a `BTreeMap`, and caches `SyntaxHighlighter` instances by `(buffer_id, Language)`. When a tab closes, changes language mode, or loads a new file in place, `App::invalidate_syntax_for_tab` (`crates/lume-tui/src/app.rs:695-699`) clears local caches and sends `SyntaxCommand::DropBuffer(tab_id)`.

Inside `SyntaxHighlighter::update` (`crates/lume-syntax/src/highlighter.rs:47-76`), Tree-sitter grammars diff `prev_text` against the new slice via `compute_input_edit` (`crates/lume-syntax/src/highlighter.rs:222-256`) and call `old_tree.edit(&edit)` before `parser.parse(text, Some(old_tree))` when the edit is smaller than the full text. Because `App::request_syntax_highlighting` sends `visible_range: 0..full_len` and `SyntaxWorker` calls `req.text.to_string()` (`crates/lume-syntax/src/worker.rs:108`), large files allocate a full `String` copy on the worker thread on each edit. On the UI thread between an edit and worker completion, `App::shift_syntax_cache_for_tab` invokes `shift_tokens_for_deltas` (`crates/lume-syntax/src/token.rs:56-93`) to adjust downstream offsets and drop tokens overlapping edited byte spans.

## Terminal frontend, rendering, and workspace security

`lume-tui` runs a single-threaded UI loop (`crates/lume-tui/src/main.rs:28-58`) receiving `AppEvent` items from a `crossterm::event::read()` thread with a `16 ms` poll timeout (`handle_tick`). `TerminalGuard::init` (`crates/lume-tui/src/terminal.rs:59-125`) enables raw mode, the alternate screen, mouse capture, focus events, and bracketed paste, and calls `supports_keyboard_enhancement()` to push Kitty `DISAMBIGUATE_ESCAPE_CODES | REPORT_ALL_KEYS_AS_ESCAPE_CODES` flags when supported. On `handle_tick`, `App` polls `.git/HEAD` synchronously every `1,500 ms` (`crates/lume-tui/src/input/mod.rs:64-68`), applies syntax responses, checks `AutoSaveController`, and drains `poll_async_saves`.

Every frame in `App::render` (`crates/lume-tui/src/render/mod.rs:26-135`) wraps output in DEC Synchronized Update markers (`\x1b[?2026h` and `\x1b[?2026l`) buffered in a `128 KiB` `BufWriter<Stdout>` (`crates/lume-tui/src/main.rs:87`). `render_pane_viewport` (`crates/lume-tui/src/render/editor.rs:18-264`) draws either a single pane or two vertical/horizontal split panes (`SplitState`), painting line numbers, git/dirty markers, syntax tokens, search hits, matching brackets, and selection highlights. Four UI and rendering limits exist at commit `a8df968`:

- `render_pane_viewport` allocates `line.to_string()` and `Vec<char>` per visible line, loops across every character on the line even past `scroll_col + text_w`, and prints raw `\t` bytes instead of spaces (`crates/lume-tui/src/render/editor.rs:90-131`, `204-215`).
- Only `cursors.primary()` selection is rendered (`crates/lume-tui/src/render/editor.rs:44-51`), and horizontal scrolling indexes `col_idx` by Unicode scalar count while `App::render` places the terminal cursor via `cursor_visual_line_col` (`unicode_width` columns + 4-column tabs).
- Floating overlays (`palette.rs:12`, `quick_open.rs:21`) clamp widths to at least `36` and `50` columns, assuming terminal widths above those floors.
- The Replace bar (`crates/lume-tui/src/search.rs:252-254`) and replace status notices (`crates/lume-tui/src/input/overlays.rs:391`, `500`) display Portuguese strings (`"Substituir por"`, `"Ocorrência substituída"`, `"Substituídas {} ocorrências"`) inside an otherwise English interface.

Explorer filesystem mutations validate workspace confinement before running syscalls (`crates/lume-tui/src/explorer.rs:226-664`). `validate_existing_ancestor_chain` and `resolve_safe_target` block `..`, root/drive prefixes, and symlinks across ancestors and targets, walking lexically up to `root_canon` to defeat symlink loops such as `ws/loop -> ws`. `ensure_dir_no_symlinks` creates intermediate directories one component at a time while checking `symlink_metadata`, and `create_file` opens targets with `create_new(true)`.

`QuickOpen` (`crates/lume-tui/src/quick_open.rs:223-371`) caps workspace scans at `50,000` files and depth `32`, skipping hidden entries, build directories (`target`, `node_modules`, `dist`, `build`, `out`, `vendor`, `.lume_tmp`, `coverage`), and listed binary extensions. It tracks visited directories by canonical path to stop directory cycles.
